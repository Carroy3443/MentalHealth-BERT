# Project 4 — Stephen Center Front-Office Simulation

Discrete event simulation of the front-office service line at the
Stephen Center homeless shelter in Omaha, NE, observed during the
6:00 PM – 8:00 PM post-dinner rush.

This folder contains every deliverable for Project 4.

## Contents

| File | What it is |
|---|---|
| `Shelter_Simulation_Presentation.pptx` | 15-slide PowerPoint deck (the main project deliverable) |
| `Shelter_Simulation_Presentation.pdf` | PDF render of the deck for quick review (optional, regenerated by `make pdf`) |
| `ShelterSimulation.alp` | Hand-crafted AnyLogic project blueprint in XML form (see notes below) |
| `AnyLogic_Build_Guide.md` | **Canonical** step-by-step instructions for building the model in AnyLogic 8.9 |
| `observation_data.csv` | Raw 30-client observation data: arrival, service start / end, server, request type, wait |
| `interarrival_times.csv` | 29 inter-arrival gaps derived from `observation_data.csv` |
| `data_analysis.py` | Python script that reads the CSVs and produces every chart used in the deck |
| `build_presentation.py` | Python script that assembles the `.pptx` from text, tables and the generated charts |
| `figures/` | All chart PNGs and `summary_stats.txt`, regenerated by `data_analysis.py` |

## How to reproduce

```bash
# 1. Install Python deps (in a venv).
pip install pandas numpy scipy matplotlib python-pptx

# 2. Regenerate every chart and the stats text file.
python data_analysis.py

# 3. Rebuild the PowerPoint deck from the (regenerated) charts.
python build_presentation.py

# 4. (Optional) Render the deck to PDF for review.
libreoffice --headless --convert-to pdf Shelter_Simulation_Presentation.pptx
```

Both Python scripts are deterministic: re-running them produces
byte-stable charts and an internally-consistent `.pptx`. Any change to
`observation_data.csv` propagates through `data_analysis.py` to the
charts and from there into the deck on the next `build_presentation.py`
run.

## About the AnyLogic model

There are two artifacts that describe the model:

1. **`AnyLogic_Build_Guide.md`** — the **canonical** description.
   It walks step-by-step through every block (Source, SelectOutput,
   Queue, Service, Sink), every parameter (interarrival distribution,
   triangular service-time bounds per request type, server count),
   every connector, and every variable / chart on the Main canvas.
   It also contains the build steps for the two improvement scenarios
   (dedicated quick-service lane, third staff member at peak).
2. **`ShelterSimulation.alp`** — a hand-crafted XML blueprint in
   AnyLogic's `.alp` style. AnyLogic `.alp` files are normally generated
   by the IDE and contain hundreds of internal IDs and visual layout
   metadata that cannot be reliably reproduced by hand. This file
   therefore documents every block, parameter, distribution and
   connector in the same XML format an `.alp` file uses, so it can be
   diffed in version control and read for reference, but it is **not**
   guaranteed to open as a fully editable model in the AnyLogic IDE.
   Follow the build guide to construct the model in AnyLogic itself.

## Three scenarios studied

| Scenario | Description | Key change vs base |
|---|---|---|
| Base model | 1 shared FIFO queue, 2 interchangeable servers | — |
| Improvement 1 | Dedicated quick-service lane | `SelectOutput` routes QQ + SR to Server A and RA + LA to Server B; each has its own queue |
| Improvement 2 | Third staff member at peak | Service block uses `time() < 60 ? 3 : 2` servers (3 staff during the 6:00–7:00 PM peak, 2 thereafter) |

All three scenarios are simulated for 120 minutes (the observation
window) over 30 replications. Headline results:

| Metric | Base | Imp 1 | Imp 2 |
|---|---|---|---|
| Avg wait (min) | 4.4 | 2.7 | 1.5 |
| Max wait (min) | 11 | 7 | 5 |
| Avg queue length | 1.6 | 1.0 | 0.5 |
| Avg server utilization | 95% | 82% | 67% |

See `figures/scenario_comparison.png` and slides 11 – 14 of the deck
for the full breakdown.
